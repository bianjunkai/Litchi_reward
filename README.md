# 超级马里奥家庭奖励中心

Vue 3 + FastAPI + SQLite 家庭奖励应用，支持孩子浏览和家长确认。默认面向单个家庭、一个孩子。

## 页面与使用方式

- **城堡**：简洁首页，仅展示可用奖励概况、学习／整理／吃饭／运动四类入口，以及下一张兑换券的目标进度。体育任务直接奖励体育徽章，不消耗星星。自选心愿和成长统计留待后续，不在本次页面调整中新增。
- **冒险**：按事项查看任务、完成条件与今日状态；孩子点击“请家长确认”进入家长解锁页，不直接发奖。
- **背包**：分为星星袋、徽章册、兑换券和奖励规则。星星明细、两段兑换进度、徽章历史均从首页移到这里，已兑换徽章继续保留收藏。
- **商城**：浏览商品并发起申请，家长确认实际消费后才扣券。
- **家长入口**：位于右上角，不占用孩子端底部导航。解锁后按今日工作台、兑换中心、任务管理、商品管理、徽章管理、记录与纠错、家庭设置分栏操作。

页面使用 URL hash 导航，例如 `#/backpack/badges`、`#/adventures/sports`、`#/parent/exchange`，支持直接打开、刷新及浏览器前进／后退。家长刷新页面须重新解锁；返回孩子页面（包括浏览器返回）会立即清除本机家长凭据并尝试撤销服务端会话，不再将解锁状态带入孩子页面。

升级保留已有资产与历史。徽章换券申请会新增申请及所选徽章关联表，不重算旧账。

### 孩子申请兑换券与家长审批

- 儿童首页的下一目标是“申请兑换券”，进入“背包 → 兑换券”选择共 5 枚徽章，类型和颜色可混合。提交后等待家长审批，尚不扣徽章、不增加券；同一孩子同时只保留一笔待审批换券申请。
- 家长在“兑换中心 → 徽章换券审批”查看具体类型、颜色和数量。批准时在同一事务内扣除孩子选中的 5 枚徽章并增加 1 张 ¥39.90 券；拒绝不改变资产。徽章已用于其他操作、被撤销或停用时，拒绝旧审批，需核对后重新申请。
- 背包徽章卡及彩色数字突出当前可用／未兑换数量，历史累计另列。使用体育徽章换券后，体育徽章可用数会减少；收藏记录继续保留。等待中的换券页面每 15 秒查询审批结果，状态变化后同步背包；回到孩子页面或重新切回浏览器也刷新数据。
- 家长在“今日工作台”发放体育或预留徽章时，可以当场选择绿、橙、红、金、银，不必修改任务的默认颜色。
- 首次升级前自动保存 `rewards.db.pre-coupon-requests.db`。新版 JSON 备份格式为 3，包含换券申请和所选徽章，仍支持导入版本 1、2 的旧备份。升级和恢复均保留现有家长凭据。

### 背包小账本

- 星星袋可按颜色和增加／减少筛选，查看任务奖励、混色兑换生活徽章、补记及撤销记录。每条显示该颜色记账后的余额，不把某一种颜色的余额当成星星总数。
- 徽章册支持按类型、颜色和可使用／已兑换／尚未启用／已撤销筛选；点收藏卡片的“查看获得记录”可定位对应徽章。获得原因、日期和换券时间保留，撤销的获得不计入累计。
- 兑换券展示获得、消费、撤销返还和扣回；消费明细保留当时的实际金额、用券数量、家长补差及不找零金额。撤销奖励账户操作不代表实际消费已退款。
- 原操作被撤销后仍可查看，同时另列反向记录；旧规则消费未记金额时不估算人民币金额。旧余额对账补录之前的历史余额无法完整还原时明确标为未知，不改写历史或当前余额。
- 每次加载 20 条，通过“再看一些记录”继续查看，不截断历史。记录按记账顺序从新到旧，时间按家庭时区显示。切换筛选会重新查询，刷新按钮会更新当前背包记录。
- 记录仅在打开对应背包分类时读取，加载失败可单独重试，不影响首页及资产概况。只读接口 `/api/backpack/ledger`、`/api/backpack/badges` 沿用家庭局域网孩子浏览权限，不开放发奖、扣款、纠错或管理凭据。

### 奖励商城与我的申请

- 商城分为“礼物架”和“我的申请”，支持名称搜索和券数筛选，地址分别为 `#/shop/catalog`、`#/shop/requests`；原来的 `#/shop` 仍可打开礼物架。
- 礼物卡展示所需券数、券总面额和还差多少张。券不足也能先申请，但家长确认时必须重新检查余额；申请不扣券、不冻结余额，多个待确认申请不代表都能兑换成功。
- 点击礼物先显示确认弹窗，选择“发送给家长”才创建申请。“再想一想”和关闭弹窗不发送申请；商品内容或价格在确认前变化时须刷新后重新确认，不静默换成新条件。
- 同一孩子、同一商品同时只创建一条待确认申请；礼物卡显示“已申请”。断线重试已有的待确认申请，即使商品后来改名或下架，也返回原申请，不覆盖当时的名称、券数和参考金额。
- “我的申请”可按等待确认、已兑换、未通过、已撤销筛选，每次加载 20 条并支持继续加载。状态计数和待确认标记不受当前筛选或分页影响，点击右上角刷新可同步其他设备的处理结果及余额。
- 已兑换和撤销记录保留实际用券、人民币消费、家长补差和不找零明细；旧记录缺失的金额不重新估算。撤销奖励账户操作不代表实际消费已退款。
- 被拒绝或已处理的商品仍可重新申请，但会创建新记录；若已存在另一条待确认申请或商品已下架，则不提供重申按钮。申请不能由孩子自行批准、扣券或撤销。
- 申请记录只在进入商城时查询，加载失败可单独重试；同步前仍可浏览礼物，但暂时不能发新申请。没有新增数据库字段，沿用现有申请和结算流水。

## NAS 部署

需要 Docker Compose v2，镜像构建时需要能够访问 Docker Hub、PyPI 和 npm。

```bash
docker compose up -d --build --wait
```

访问 `http://NAS_IP:18736`，健康检查使用同一端口的 `/api/health`。可在项目根目录的 `.env` 中设置 `WEB_PORT` 换端口；开发服务的默认端口仍为 8080。后端只在 Compose 内部网络开放，不另外映射 8000 端口。

### 构建代理（群晖等 NAS）

需要代理下载 pip/npm 依赖时，在项目根目录的 `.env` 中添加：

```dotenv
WEB_PORT=18736
BUILD_PROXY=http://proxy-host:port
BUILD_NO_PROXY=localhost,127.0.0.1,api,web
```

如果已有 `.env`，仅合并以上键，保留现有 PIN 等配置；不要直接覆盖。将代理地址换成实际可达的局域网代理，并确认代理端允许 NAS 及其构建网络访问。个人代理地址示例不提交到仓库。

Compose 把代理作为 Docker 预定义构建参数传入两个服务，同时设置大小写形式，覆盖 Python/pip 和 Node/npm 的构建下载。HTTPS 目标仍使用同一个 `http://` 代理地址，通过 CONNECT 隧道访问；不要因此把代理 URL 改成 `https://`。不在 Dockerfile 中声明代理 `ARG/ENV`，也不将代理传给应用运行容器，NAS 内网浏览和 API 健康检查无需经过代理。自定义缓存与历史导出工具仍可能记录构建配置，不要把带密码的代理配置提交到仓库或公开日志。

**拉取基础镜像是另一层配置。** `python:3.12-slim`、`node:22-alpine`、`nginx:1.27-alpine` 的拉取由 Docker 守护进程或所用构建器负责；本项目的构建参数不能代替它们的代理配置。在 SSH 中 `export HTTP_PROXY` 或给 Docker CLI 添加代理变量，也不等于给长期运行的 Docker 守护进程设置代理。

若在 `load metadata`／拉取基础镜像阶段超时，应先检查群晖容器服务的代理和构建器配置；这可能需要重启容器服务，影响其他容器，先确认 DSM／Container Manager 版本及现有配置再操作，不要盲目覆盖 Docker 配置。若镜像拉取正常，只有 `pip install`／`npm ci` 失败，则检查构建代理是否可达。代理只解决网络路径，不关闭 HTTPS、证书或软件包完整性验证。

### 首次使用与数据

首次打开右上角“家长入口”，设置 **6–12 位数字 PIN**；没有默认 PIN。也可复制 `.env.example` 为 `.env`，填入可选的 `PARENT_PIN` 作为首次初始化 PIN。PIN 设置后以加盐哈希保存，后续在家长中心的“家庭设置”更换，环境变量不会覆盖已经设置的 PIN。

旧版本若曾配置 `PARENT_PIN=1234`，升级前请移除该变量或改成 6–12 位数字。旧版本的 PIN 请求头不再提供管理权限。家长解锁后得到 30 分钟的临时会话，交给孩子前点击“返回孩子模式”，系统会自动锁定。5 分钟内错误尝试 5 次后会暂时锁定登录。

奖励数据保存在 `./data/rewards.db`。首次启动从零资产开始，不自动赠送演示星星或兑换券。升级时保留旧资产和历史，迁移前生成 `.pre-v2.db` 副本，并将旧版本余额与流水间的差额标为“旧版本余额对账补录（原始原因未知）”。不要删除 NAS 的 `data` 目录。

容器服务会监听 NAS 的网络接口；Compose 本身不配置防火墙。请在 NAS/路由器中限制为家庭网络，勿直接设置公网端口转发。

## 云端／本地开发

需要 Python 3.12+ 和 Node.js 22+。在仓库根目录执行：

```bash
python3 -m venv backend/.venv
backend/.venv/bin/python -m pip install -r backend/requirements.txt
npm --prefix frontend ci --cache /tmp/litchi-reward-npm-cache
npm run dev
```

一条 `npm run dev` 命令同时启动 FastAPI 和 Vite，并等待后端健康后开放前端 8080 端口。按 Ctrl+C 停止本次启动的服务。默认使用仓库根目录 `data/rewards.db`；可设置 `DB_PATH` 切换数据库、`PORT` 切换前端端口。仓库根目录的 `.env` 会由启动器加载。

单独启动前端并不会启动 API；页面会明确显示无法连接和重试入口。`npm run build` 只生成静态文件，不启动网页服务器。

## 奖励规则与账目

### 上架门票、充值券等兑换奖励

进入“家长中心 → 奖励上架”（工作台也有快捷入口），点击“新增奖励”，或使用门票、手表充值、玩具模板。填写奖励名称、兑换说明、所需通用券（1–5 张）和可选参考金额，再确认上架；也可以先“保存为未上架”。这只是商城奖励，不会直接增加孩子的兑换券。

可上传小于 5MB 的 JPG、PNG、WebP；浏览器将图片缩至最长边 512px、最多 96KB，并通过重新绘制去掉原图元数据。压缩图保存在 NAS 的 SQLite 中，随 JSON 备份导出，不依赖第三方图床；不传图片或图片读取失败时使用备用图标。不支持 SVG、HEIC 或外部图片网址。

管理页可搜索、筛选、编辑、上架和下架奖励。下架不删除历史申请；修改名称或用券数量不改写已经提交的申请快照。“查看孩子商城”会自动锁定家长权限。最终扣券仍须家长在兑换中心确认，原有“5 枚徽章换 1 张 ¥39.90 通用券”的规则不变。

升级图片功能前自动保存 `rewards.db.pre-product-images.db`，只增加可选图片字段，不重算资产。导入旧版备份时，没有图片的奖励自动保留备用图标。JSON 恢复上限仍为 8MB，大量图片会增大备份；完整数据库也可通过 NAS 备份保存（备份数据库前先停止服务）。

### 记账约定

- 学习／读书奖励橙色星星，整理桌子和物品奖励绿色星星，按时吃完饭奖励红色星星。每项每天最多 1 枚，没完成不发放；同一颜色事项即使建立多个任务也不能重复发放。金色星星未设置条件，暂不发放或参与兑换。
- 任务按家庭时区每天限领一次，默认 `Asia/Shanghai`，零点换日。时间戳保存为 UTC，界面按家庭时区显示。
- **5 枚星星代币 → 1 枚生活徽章**。可以混合橙、绿、红三种颜色，默认按学习、整理、吃饭的顺序扣除。代币只能兑换生活徽章，不能兑换体育或预留徽章。
- **任意 5 枚已启用且未兑换的徽章 → 1 张兑换券**。孩子选择类型、颜色与数量，家长审批；每个选定颜色内优先使用较早获得的徽章，每枚只能使用一次。预留徽章未启用前不参与。
- 固定四种徽章：体育（奇诺比奥）、生活（星星）、预留 A（火焰花）、预留 B（王冠）。体育及预留徽章通过家长设置的独立任务条件获得；预留徽章默认停用。每种均支持绿、橙、红、金、银，颜色只表示外观／等级，不自动绑定学习、运动等条件。
- 徽章区分“历史累计”“未兑换持有量”“可参与兑换数量”。停用不删除历史，也不销毁已持有的徽章；已兑换的徽章仍保留收藏，并标记“已兑换”。
- **每张兑换券价值 ¥39.90，可以累积；每笔最多使用 5 张，最多抵用 ¥199.50。** 不提供兑换券折现或找零功能。金额在数据库中保存为整数“分”，不使用浮点数计算。
- 申请保存商品名称、计划用券数量和参考消费金额快照。孩子申请不扣券，相同待处理商品不会重复申请；家长填写实际消费金额和本次用券数量后才确认扣券。改商品不会改变旧申请。
- 实际消费高于券总额时，家长须明确勾选同意补差额才可确认；低于时差额不找零、不折现，也不返还为其他资产。例如 1 张券消费 ¥50.00，记录家长补差 ¥10.10；消费 ¥30.00，则记录不找零 ¥9.90。
- 发放奖励、代币换徽章、徽章换券和实际消费分别记录，消费流水单独保存实际金额、用券张数、家长补差、不找零金额和说明。
- 所有扣款、奖励和撤销使用写事务；同一申请只能处理一次，资产有数据库层非负约束。
- 纠错可以按原操作撤销，留下反向流水并保留历史。误领任务撤销后可重新领取。资产或徽章已被后续操作使用时，需要先按相反顺序撤销后续操作。
- 家长工作台显示今日发放、可用券及最近 5 条待处理申请（总数不截断），支持按待发放／已发放筛选任务。消费审批默认只看待确认申请，可按名称、`#申请编号`、状态和家庭日期查询，每页 20 条，支持继续加载完整历史。
- 消费确认前再次列出实际金额、扣券张数、补差、不找零及扣券后余额；修改金额或张数后，须重新勾选补差同意。余额不足不能确认。仅登记家庭账本，不会代为付款。
- “记录与纠错”支持操作类型／状态、资产／收支方向、原因、`#操作编号`、家庭日期筛选，分页读取完整记录，不再只显示最近 500／1000 条。旧列表 API 保留以兼容旧客户端。
- 撤销前只读预览资产变化、扣回／恢复徽章及阻塞的后续操作，提交时再次核对。资产补记／纠错须填写原因、核对前后余额；余额变化会拒绝旧确认，重新加载后再操作。控制台加载失败或写请求结果不明时暂停写操作，防止重复提交。撤销只纠正账本，不代表实际消费退款。

兑换比例、券面额和单笔上限按上述家庭约定固定，由后端强制校验；控制台可修改家庭时区、任务条件、徽章颜色及启用状态。手动资产调整仅用于补记／纠错，须填写原因，不代表日常任务规则。

### 修正旧版规则

旧版曾错误地按 1 枚徽章换 1 张券，并允许星星换其他徽章。更新时自动将**未来**规则改为本说明，迁移前在数据库旁生成 `.pre-family-v1.db` 副本。已有资产、已获得徽章、已兑换标记及历史扣款均保留，不自动重算或追回；没有实际消费金额的旧流水标为“旧规则”，不会伪造人民币金额。旧版超出 5 张的待处理申请须拒绝后重新申请。

## 备份与恢复

家长控制台可导出 JSON 备份，包含家庭资产、规则、商品和历史，不含 PIN 哈希及会话。恢复先检查表结构、关联关系、非负余额和流水对账；验证失败不会替换数据。

恢复成功前，当前数据会先保存到 `data/backups/before-restore-*.json`，原 PIN 和登录配置保留。恢复会替换当前奖励数据，界面会要求确认。可选择该安全副本再恢复。新版导出为版本 2；导入旧版版本 1 时同样只修正未来规则，保留历史资产和扣款。

## PWA 与离线

生产构建注册 Service Worker，缓存页面外壳、图标和静态资源；不缓存任何 `/api` 请求、PIN、会话或奖励余额。离线可以打开页面外壳并看到断线提示，不能离线发奖或扣款。

Service Worker 要求 HTTPS 或 localhost 安全上下文。NAS 的普通局域网 HTTP 地址仍可在线使用，但完整离线缓存和安装能力取决于浏览器；需要这些功能时，通过 NAS 反向代理配置可信 HTTPS。
